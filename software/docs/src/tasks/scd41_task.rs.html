src/tasks/scd41_task.rs — periodic CO₂, temperature, and humidity measurement

This task takes one full SCD41 reading every ten seconds. It shares I²C0 safely with the particle-sensor task, leaves that bus available during the SCD41’s five-second conversion, stores successful readings in external-memory history, and retries safely after errors.

What this file does

The task communicates with a Sensirion SCD41 at its factory I²C address, 0x62. A successful reading contains carbon-dioxide concentration in parts per million, plus raw temperature and humidity words. The raw values are converted to degrees Celsius and relative humidity only when printed or returned by the web API.

  1. Bring the sensor into its idle state and confirm that it answers with a valid serial number.
  2. Start one on-demand CO₂, temperature, and humidity conversion.
  3. Release the shared I²C bus for the sensor’s required 5,000 ms conversion time.
  4. Reacquire the bus, read three CRC-protected words, save the result, and print it to the USB serial console.
  5. Wait until the next ten-second schedule deadline. On a failure, pause for one second and reinitialise before trying again.
The task’s ten-second interval is measured from scheduled start times, not from the end of one successful read. A normal conversion takes about five seconds, leaving roughly five seconds for the other task to use the shared bus before the next conversion begins.

Schedule

One normal cycle starts immediately, waits 5,000 ms for conversion, reads and stores the result, then waits until ten seconds after that cycle started to begin again. The schedule therefore targets six conversions per minute.

MEASUREMENT_INTERVAL_MS is public because the history module uses it to calculate the one-day capacity. One day contains 86,400,000 milliseconds, so ten-second readings produce 8,640 retained readings.

After an error the task waits one second. It does not continue the old ticker schedule; a later successful initialisation resets the schedule so the next conversion starts immediately.

Recovery state

needs_init is true at boot and after every failed start or read. The task then locks the bus, recovers it, and creates a short-lived driver that borrows that controller.

stop_periodic_measurement() sends command 0x3F86 (stop_periodic_measurement) and waits 500 ms. Calling it is safe even after reset when periodic measurement was not running. It makes the sensor idle, which is required before single-shot commands are accepted.

serial_number() sends command 0x3682 (get_serial_number), waits 1 ms, reads nine bytes, validates three CRC bytes, and combines the three 16-bit words into a 48-bit number. A valid result confirms that the device and transfer are working; it is printed as twelve hexadecimal digits.

The outer braces are important: they end the mutex guard, controller, and driver before the retry delay or later conversion starts.

Start command

acquire() always executes bus recovery before rebuilding the hardware controller at 100 kHz. Recovery drives SCL through nine pulses and sends a manual STOP condition, returning a bus that may have been left in an undefined state by a previous failed transfer to idle.

start_single_shot() writes command 0x219D (measure_single_shot, the SCD41 command that starts a full CO₂, temperature, and humidity conversion). This is a blocking I²C write, so it returns either immediately after the transfer or with a bus error. No sensor value exists yet.

The lock ends at the closing brace. If the start write failed, no result can become available, so the task marks the sensor as needing initialisation, waits one second, and restarts recovery.

Shared-bus rule

The SCD41 needs exactly 5,000 ms after command 0x219D (measure_single_shot, started by start_single_shot()). The task waits without holding the mutex, allowing the SPS30 task to transfer during almost all of that interval.

read_measurement() writes command 0xEC05 (read_measurement), waits 1 ms, then reads nine bytes. Bytes 0–1, 3–4, and 6–7 are big-endian words. Bytes 2, 5, and 8 must match Sensirion CRC-8: polynomial 0x31, initial value 0xFF, no reflection, and no final XOR. A failed transfer yields Bus(...); a mismatched check byte yields Crc.

For a successful result, CO₂ is stored as the reported integer in ppm. The driver calculates temperature by taking the raw temperature word, multiplying it by 175, dividing by 65,535, then subtracting 45. It calculates relative humidity by multiplying the raw humidity word by 100 and dividing by 65,535. The task prints those converted values and sends the original measurement to history.

Fixed schedule

After an error, the task waits one second and the next loop pass must initialise the sensor. After success, ticker.next().await waits only until the next previously calculated deadline.

This differs from waiting another ten seconds after a read. If the read completes around five seconds after the start, the next wait is roughly five seconds. Short variations in transfer duration do not gradually move the schedule later.

If a cycle takes longer than a deadline, the ticker reports the missed deadline without trying to run several measurements at once. The next loop pass proceeds with one new conversion.

Complete dependent component: the SCD41 driver

Result, errors, and CRC

Measurement has three exact fields: co2_ppm: u16, temperature_raw: u16, and humidity_raw: u16. Temperature is calculated as −45 + (175 × temperature_raw / 65535) degrees Celsius. Relative humidity is calculated as 100 × humidity_raw / 65535 percent. In each formula, the raw 16-bit word is first scaled to the sensor’s documented range, then converted to the displayed unit.

Error::Bus(I2cError) means the I²C transfer failed, such as no acknowledgement or timeout. Error::Crc means the sensor replied but a check byte did not match. crc8() starts with CRC8_INIT = 0xFF, processes each data byte most-significant-bit first, and uses CRC8_POLYNOMIAL = 0x31 whenever the current high bit is set. There is no bit reflection and no final XOR. The driver checks this CRC separately for every two-byte returned word.

The driver deliberately performs each command write and subsequent response read as two separate I²C transactions. The SCD4x protocol requires this; it does not use a repeated-start combined write/read transaction.

Complete dependent components: I²C bus, shared state, history, and PSRAM

Shared I²C bus interface

I2cBus owns five exact fields: i2c0: I2C0, sda: SdaPin, scl: SclPin, clocks: &'static Clocks<'static>, and delay: Delay. SdaPin is the concrete alias GpioPin<I2C_SDA_PIN>; SclPin is GpioPin<I2C_SCL_PIN>. The named constants are I2C_SDA_PIN = 5, I2C_SCL_PIN = 6, and I2C_FREQUENCY_KHZ = 100.

The sensor tasks receive SharedI2cBus = Mutex<CriticalSectionRawMutex, I2cBus>. After a task awaits the lock, I2cBus::acquire() calls recover_i2c_bus(sda, scl, delay), then builds the 100 kHz temporary controller. recover_i2c_bus() configures both pins as pulled-up open-drain outputs, pulses SCL nine times using five-microsecond half periods, then produces a STOP condition by releasing SDA high while SCL is high. This is the named function that returns a bus left by a failed transfer to idle before the next SCD41 command.

Shared state interface

shared_state::init(psram) runs before either sensor task starts. It requests an SCD41 slice of SCD41_CAPACITY = HISTORY_WINDOW_MS / SCD41_INTERVAL_MS = 8,640 optional samples and an SPS30 slice of SPS30_CAPACITY = HISTORY_WINDOW_MS / SPS30_INTERVAL_MS = 17,280 optional samples. HISTORY_WINDOW_MS is 86,400,000 ms, one day.

Ring-buffer implementation

MeasurementHistory<T> owns an externally supplied permanent slice of Option<T>, plus next write index, current len, and total pushed count. new(entries) rejects an empty slice. push(value) writes at next, advances that index with wraparound, limits len to capacity, and increments pushed.

capacity() returns slice length; len() returns retained entries; next_sequence() returns pushed; and first_sequence() returns pushed − len. This formula means that once old entries are overwritten, the first retained sequence advances by one for every replacement. get(sequence) subtracts first_sequence() and delegates to get_oldest(index). The private helper calculates the physical oldest index, using next when the buffer is full, and returns the copied entry or None.

PSRAM allocator

Psram::init() maps the ESP32-S3R8 external PSRAM before Wi-Fi and sensor tasks begin, then records the start and end address of the mapped window. free_bytes() reports end − next. alloc_slice<T>(len, value) aligns the next address for T, checks multiplication and address arithmetic for overflow, verifies that the request fits, fills every element with value, advances the permanent allocation pointer, and returns a permanent mutable slice. It returns None rather than forming an invalid address when PSRAM is insufficient.

If either history allocation fails, init() returns None. The sensor tasks still measure and print results, but both publish_* functions drop readings because their optional histories are absent, and the web API reports empty histories.
