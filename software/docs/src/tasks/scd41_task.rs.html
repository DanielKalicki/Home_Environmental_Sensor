src/tasks/scd41_task.rs — periodic CO₂, temperature, and humidity measurement

This task takes one full SCD41 reading every ten seconds. It shares I²C0 safely with the eight other sensor tasks, leaves that bus available during the SCD41’s five-second conversion, discards the first reading after every start-up, stores later readings in external-memory history, and retries safely after errors.

What this file does

The task communicates with a Sensirion SCD41 at its factory I²C address, 0x62. A successful reading contains carbon-dioxide concentration in parts per million, plus raw temperature and humidity words. The raw values are converted to degrees Celsius and relative humidity only when printed or returned by the web API.

  1. Bring the sensor into its idle state, then confirm that it answers correctly and report how it is configured: serial number, sensor variant, temperature offset, altitude, ambient pressure, and the four automatic self-calibration settings.
  2. Start one on-demand CO₂, temperature, and humidity conversion.
  3. Release the shared I²C bus for the sensor’s required 5,000 ms conversion time.
  4. Reacquire the bus and read three CRC-protected words.
  5. Discard the first reading after each initialisation, then save every later one and print all of them to the USB serial console.
  6. Wait until the next ten-second schedule deadline. On a failure, pause for one second and reinitialise before trying again.
The task’s ten-second interval is measured from scheduled start times, not from the end of one successful read. A normal conversion takes about five seconds, leaving roughly five seconds for the other eight tasks to use the shared bus before the next conversion begins.
All eleven start-up exchanges are read-only. The task reports what the sensor is configured to do; it never writes a setting, so nothing printed at start-up was chosen by this firmware.
DISCARDED_WARMUP_READINGS is 1. The first reading after every initialisation — at boot and after each recovery — is printed with a (warm-up, discarded) marker and kept out of the history, because the sensor’s first conversion after being idled reflects its self-heating rather than the room.

Ten seconds, and the comment is precise about what it measures: the time between the starts of two conversions, not the gap between them. About five of those ten seconds are the sensor converting; the rest is idle time in which other tasks use the bus.

This is the only pub item in the file apart from the task itself. shared_state.rs imports it as SCD41_INTERVAL_MS and computes SCD41_CAPACITY = HISTORY_WINDOW_MS / SCD41_INTERVAL_MS = 86,400,000 / 10,000 = 8,640 retained readings, one full day.

Configuration

One second. Used at both failure points: a failed initialisation and a failed measurement.

Its purpose is to stop a disconnected sensor from spinning. /// How many readings are dropped after the sensor is started.
///
/// The first single-shot conversion runs before the sensor's own temperature
/// has settled, so its result is not representative. Discarded readings are
/// still read and printed, they are only kept out of the published history, so
/// one unsettled value cannot distort the charts. The count restarts after
/// every re-initialisation, including the one following a bus error. Set to 0
/// to publish every reading.
const DISCARDED_WARMUP_READINGS: u32 = 1;
Data quality

Exactly one reading is thrown away after every initialisation.

Why. The SCD41 measures its own temperature to compensate the CO₂ figure. Immediately after power-up or after leaving idle mode, the sensor's internal heating has not reached equilibrium, so the first conversion is taken under conditions that will not recur. Publishing it would put one visibly wrong point at the start of every chart.

Discarded means withheld from the history, not unread. The reading is still taken and still printed on the console, marked (warm-up, discarded). Nothing is hidden from someone watching the serial output; only the stored history is protected.

The count restarts on every re-initialisation. That includes recovery from a bus error, because a bus error is followed by stop_periodic_measurement, which puts the sensor through the same unsettled transition again.

The comment states the disabling value explicitly: setting this to 0 makes warmup_remaining > 0 false on the first pass, so every reading is published.

The type is u32 because the counter it initialises is decremented; a signed type would allow it to go negative, and a u8 would cap the configurable warm-up at 255 readings for no reason.

Identity

Command 0x3682, 1 ms wait, then a nine-byte read: three 16-bit words each followed by its own check byte. The driver validates all three and combines the words into one 48-bit number in a u64.

This is the strongest evidence that the wiring is sound. A serial number is effectively random, so three independent words all passing their CRC is very unlikely to happen by accident on a noisy bus.

Command 0x2318, one word, converted by the driver to 175 × raw / 65535 as an f32.

Configuration

Command 0xE000, one word. The sensor stores hectopascals, so the driver widens the value to u32 and multiplies by 100.

acquire() does two things before returning a usable controller: it bit-bangs nine clock pulses and a STOP condition on GPIO5/GPIO6 to force the wires back to idle, then it builds a fresh 100 kHz I²C block on them.

The recovery step matters because esp-hal abandons a transfer on a NACK without emitting the closing STOP. Result translation

This is the only place the eleven checks are called, and the only place their error is turned into text.

One message, not eleven. Printing inside each check would need the same line repeated eleven times. The error value already says what went wrong — Bus(…) for a failed transfer, Crc for a corrupted answer — and the checks abort at the first failure, so exactly one message can ever be produced per attempt.

The match is the last expression in the function, so its value is the return value; there is no return keyword.

Splitting this into eleven separate lock/acquire cycles would let other tasks interleave between checks, at the cost of eleven bus recoveries and eleven lock acquisitions for a sequence that runs only at start-up and after an error. Holding the lock throughout is the simpler and cheaper choice.

Writes command 0xEC05, waits 1 ms, then reads nine bytes in a second transaction. Bytes 0–1, 3–4 and 6–7 are big-endian words; bytes 2, 5 and 8 are Sensirion CRC-8 check bytes (polynomial 0x31, initial value 0xFF, no reflection, no final XOR), each checked separately.

Binds the Measurement by value; it is three u16 fields and is Copy, so it can be handed to publish_scd41 and still be read afterwards for printing.

                needs_init = false;
Recovery state

Cleared only here, on a complete success. A successful read is proof that the sensor is present, configured and in the expected mode, which is exactly what the initialisation sequence establishes — so repeating it would tell the task nothing new.

                // Reported either way, but withheld from the history until the
                // sensor has settled.
                let settling = warmup_remaining > 0;
Warm-up decision

One boolean, computed once, used three times below: to decide whether to decrement, whether to publish, and what suffix to print. Computing it once rather than testing warmup_remaining > 0 repeatedly avoids the three uses disagreeing after the counter changes.

The comment states the rule exactly: the reading is printed either way, and only its entry into the stored history is withheld.

                if settling {

                    shared_state::publish_scd41(measurement).await;

Shared state

Exactly one of the two happens. While settling, the counter is decremented and nothing is stored; once it reaches zero, every reading is stored and the counter is never touched again until the next initialisation.

publish_scd41() locks the history mutex, writes the sample with its timestamp into the ring buffer in PSRAM, advances the write index, and releases the lock. It is .awaited because of that lock, not because of any slow work — the write itself is a few stores.

The buffer holds SCD41_CAPACITY = 8,640 slots, which at one reading per ten seconds is exactly 24 hours. When full it overwrites the oldest entry.

Serial console output

The measurement as stored is raw: co2_ppm is already in ppm, but temperature and humidity are unconverted 16-bit words. The two method calls perform the conversions — −45 + 175 × raw / 65535 degrees Celsius, and 100 × raw / 65535 percent — for display only. The raw form is what goes into the history, so the conversion is never applied twice.

The trailing {} takes either the warning suffix or an empty string, so a settled reading prints with no marker at all and a discarded one is unmistakable:

CO2: 812 ppm, temperature: 22.4 C, humidity: 43.1 % (warm-up, discarded)
CO2: 795 ppm, temperature: 22.4 C, humidity: 43.0 %

Discarded readings are printed rather than hidden so that a silent console unambiguously means the sensor is not answering, never that its output is being suppressed.

                // Begin a fresh fixed schedule after recovery; this read-out
                // becomes the first deadline of the new schedule.
                if reinitialized {
                    ticker.reset();
                }
Schedule repair

Uses the snapshot taken before needs_init was cleared, so it fires only on the first successful read after an initialisation.

reset() discards the old deadline and restarts the ten-second step from this instant. Without it, the ticker would still be holding a deadline calculated before the outage; if the sensor had been down for a minute, the next await would return immediately and the six missed deadlines would produce a burst of back-to-back conversions.

It is placed after the read rather than after initialize() so that the new schedule is anchored to a confirmed working read-out.

                // `Ticker` advances from its previous deadline instead of from
                // this call, equivalent to FreeRTOS `vTaskDelayUntil()`.
                ticker.next().await;
Fixed-rate wait

Waits until the next ten-second deadline, not for a further ten seconds. Since read_once has just consumed about five seconds, this typically waits about five — and the spacing between conversion starts stays at ten seconds regardless of how long the bus contention made the cycle.

The comparison with FreeRTOS vTaskDelayUntil() is exact: both compute the wake time from a stored previous deadline. The alternative, Timer::after_millis(10_000), is the equivalent of vTaskDelay() and would let the schedule slip a little further on every pass.

            }
End of the success arm

Closes the Ok arm. Note the wait happens inside the arm, not after the match — the two arms wait for different reasons and for different durations.

            Err(error) => {
                needs_init = true;
                println!("SCD41: measurement failed: {:?}, recovering bus", error);
                Timer::after_millis(ERROR_RETRY_DELAY_MS).await;
            }
Failure arm

Three actions, in this order. Setting needs_init makes the next pass re-run the full check sequence, because after a failed exchange the sensor's mode is unknown. The message prints the error variant — Bus(…) or Crc — which distinguishes a wiring or acknowledgement problem from corrupted data on an otherwise working link.

The one-second wait replaces ticker.next(): the ticker is deliberately not advanced here, and its stale deadline is dealt with by the reset() after the next successful read. Nothing is published, so a failure leaves a visible gap in the history rather than a fabricated value.

Result, errors, and CRC

Measurement has three exact fields: co2_ppm: u16, temperature_raw: u16, and humidity_raw: u16. Two methods perform the conversions on demand: temperature_celsius() returns −45 + (175 × temperature_raw / 65535) degrees Celsius, and humidity_percent() returns 100 × humidity_raw / 65535 percent. In each formula, the raw 16-bit word is first scaled to the sensor’s documented range, then converted to the displayed unit. This task calls both at lines 151–152, for printing only; the raw form is what is stored in the history, so the conversion is never applied twice and never loses precision in storage.

The struct is Copy — three u16 fields, six bytes — which is why line 145 can hand it to publish_scd41() by value and the println! that follows can still read it.

Error::Bus(I2cError) means the I²C transfer failed, such as no acknowledgement or timeout. Error::Crc means the sensor replied but a check byte did not match. crc8() starts with CRC8_INIT = 0xFF, processes each data byte most-significant-bit first, and uses CRC8_POLYNOMIAL = 0x31 whenever the current high bit is set. There is no bit reflection and no final XOR. The driver checks this CRC separately for every two-byte returned word.

The driver deliberately performs each command write and subsequent response read as two separate I²C transactions. The SCD4x protocol requires this; it does not use a repeated-start combined write/read transaction.

Complete dependent components: I²C bus, shared state, history, and PSRAM

Shared I²C bus interface

I2cBus owns five exact fields: i2c0: I2C0, sda: SdaPin, scl: SclPin, clocks: &'static Clocks<'static>, and delay: Delay. SdaPin is the concrete alias GpioPin<I2C_SDA_PIN>; SclPin is GpioPin<I2C_SCL_PIN>. The named constants are I2C_SDA_PIN = 5, I2C_SCL_PIN = 6, and I2C_FREQUENCY_KHZ = 100.

The sensor tasks receive SharedI2cBus = Mutex<CriticalSectionRawMutex, I2cBus>. After a task awaits the lock, I2cBus::acquire() calls recover_i2c_bus(sda, scl, delay), then builds the 100 kHz temporary controller. recover_i2c_bus() configures both pins as pulled-up open-drain outputs, pulses SCL nine times using five-microsecond half periods, then produces a STOP condition by releasing SDA high while SCL is high. This is the named function that returns a bus left by a failed transfer to idle before the next SCD41 command.

Shared state interface

shared_state::init(psram) runs before any sensor task starts. It reserves one slice per sensor history — eight in total, for the SCD41, SPS30, BME690, AS7343, BMP581, OPT4048, SHT41 and BMM350. Each capacity is derived the same way, HISTORY_WINDOW_MS / sensor_INTERVAL_MS, where HISTORY_WINDOW_MS is 86,400,000 ms, one day. The interval is imported from each task’s own MEASUREMENT_INTERVAL_MS, so changing this file’s interval changes its capacity automatically. SCD41_CAPACITY is therefore 86,400,000 / 10,000 = 8,640, and SPS30_CAPACITY is 86,400,000 / 5,000 = 17,280.

Ring-buffer implementation

MeasurementHistory<T> owns an externally supplied permanent slice of Option<T>, plus next write index, current len, and total pushed count. new(entries) rejects an empty slice. push(value) writes at next, advances that index with wraparound, limits len to capacity, and increments pushed.

capacity() returns slice length; len() returns retained entries; next_sequence() returns pushed; and first_sequence() returns pushed − len. This formula means that once old entries are overwritten, the first retained sequence advances by one for every replacement. get(sequence) subtracts first_sequence() and delegates to get_oldest(index). The private helper calculates the physical oldest index, using next when the buffer is full, and returns the copied entry or None.

PSRAM allocator

Psram::init() maps the ESP32-S3R8 external PSRAM before Wi-Fi and sensor tasks begin, then records the start and end address of the mapped window. free_bytes() reports end − next. alloc_slice<T>(len, value) aligns the next address for T, checks multiplication and address arithmetic for overflow, verifies that the request fits, fills every element with value, advances the permanent allocation pointer, and returns a permanent mutable slice. It returns None rather than forming an invalid address when PSRAM is insufficient.

If any history allocation fails, init() returns None. The sensor tasks still measure and print results, but every publish_* function drops readings because the histories are absent, and the web API reports empty histories.
