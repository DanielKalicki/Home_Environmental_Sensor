src/tasks/sps30_task.rs — periodic particulate-matter measurement

This task starts the SPS30 particle sensor’s continuous measurement mode, waits for a fresh sample, reads and validates ten values every five seconds, saves successful results in external-memory history, and safely reinitialises after an error.

What this file does

The Sensirion SPS30 measures airborne particulate matter continuously after it receives a start command. This task starts that mode after boot or recovery, then takes one reading every five seconds. Before each reading, it asks the sensor up to thirty times whether fresh data is ready. Each poll is separated by 100 ms and releases the shared I²C bus while waiting.

A complete sensor result contains ten floating-point values: four mass concentrations, five particle-number concentrations, and a typical particle size. The task prints all ten values to the USB serial console. It stores the complete result in history, although the web server publishes only the four mass concentrations and the typical particle size.

The SPS30 produces new values about once per second, while this task samples every five seconds. The task does not try to retrieve the values produced between its scheduled reads; it records the most recently available result at each read.

Dependencies

Measurement is the ten-value result structure. Error distinguishes a failed I²C transfer from a CRC mismatch. Sps30 is the protocol driver, and SharedI2cBus prevents the SPS30 and SCD41 transfers from overlapping.

The task itself does not allocate memory. Its temporary driver and I²C controller exist only while their local scope holds the bus mutex.

Schedule

The normal interval is five seconds. A one-day history therefore needs 17,280 entries, which is the capacity reserved for SPS30 readings when PSRAM is available.

At most thirty data-ready checks are made, separated by 100 ms. The check window is therefore about three seconds, plus the short I²C transfers. This is less than the five-second task interval, leaving time to read and store the result.

Any failed serial-number, start, readiness, or data-read operation enters recovery. The task waits one second before trying initialisation again.

Waiting for fresh data lines 18–38

async fn read_when_ready(bus: &'static SharedI2cBus) -> Result<Measurement, Error> {
    for _ in 0..DATA_READY_POLL_ATTEMPTS {
        let ready = { /* lock, recover bus, ask is_data_ready */ };
        if ready { break; }
        Timer::after_millis(DATA_READY_POLL_DELAY_MS).await;
    }
    let mut bus = bus.lock().await;
    let mut i2c = bus.acquire();
    let mut sensor = Sps30::new(&mut i2c);
    sensor.read_measured_values().await
}
Polling

Every readiness check locks the bus only long enough to recover it and exchange the command. If the flag is not set, the closing brace drops the mutex guard before the 100 ms timer wait. The SCD41 task can therefore use I²C0 between checks.

is_data_ready() sends command 0x0202 (read_data_ready_flag), waits 5 ms, reads one CRC-protected word, and reports true only when its low byte is 0x01.

No-ready after all thirty attempts is not an error. The function still calls read_measured_values(), which returns the latest sensor values. An actual bus or CRC failure during that read remains an error and triggers recovery.

Start state

At boot and after a failed operation, needs_init is true. The task reads the serial number first to confirm device presence. Command 0xD033 (read_serial_number) returns a 32-byte NUL-terminated ASCII field. The task uses the reported character count, converts only that prefix to UTF-8, and prints <non-ascii> if it is not valid text.

The SPS30 rejects the start command while it is already measuring. The task consequently sends command 0x0104 (stop_measurement) first, ignoring its result because an idle sensor may reject the stop command. It then sends command 0x0010 (start_measurement) with argument 0x0300 (big-endian IEEE-754 float output format), and waits 20 ms for each control command.

The start command immediately starts the fan and continuous measuring. The first values normally appear after about one second; the driver notes that values become stable only after roughly thirty seconds. The task records early values too; it does not discard a warm-up period.

Complete result

A successful result is timestamped and appended to history. It is also printed in three groups: four mass concentrations in micrograms per cubic metre, five number concentrations in particles per cubic centimetre, and typical particle size in micrometres.

In the driver, command 0x0300 (read_measured_values) returns 60 bytes: twenty CRC-protected 16-bit words. The driver removes the 20 CRC bytes, combines the remaining 40 data bytes into ten four-byte groups, and interprets each group as a big-endian IEEE-754 floating-point value.

After the first successful read following initialisation, ticker.reset() establishes a new schedule. Then ticker.next().await waits until five seconds after that read’s schedule point, rather than waiting a further five seconds after every operation. This prevents small transfer-time variations from accumulating into schedule drift.

Dependent component: the SPS30 driver

The driver is an allocation-free object containing only a borrowed I²C controller and the fixed SPS30 seven-bit address, 0x69. It sends commands as big-endian 16-bit values. Returned two-byte words are followed by CRC-8 bytes using polynomial 0x31, initial value 0xFF, no reflection, and no final XOR.

Each command-and-response read is intentionally two separate I²C transactions, not a repeated-start combined write/read, because that is what the SPS30 protocol requires.

Complete SPS30 driver reference

Sps30<'a, 'd, T> has two fields: i2c: &'a mut I2C<'d, T, Blocking> and address: u8. new() uses DEFAULT_ADDRESS = 0x69; with_address() accepts another seven-bit address.

Complete I²C, shared-state, history, and PSRAM dependencies

Shared I²C0

I2cBus owns i2c0: I2C0, sda: SdaPin, scl: SclPin, clocks: &'static Clocks<'static>, and delay: Delay. SdaPin = GpioPin<I2C_SDA_PIN> and SclPin = GpioPin<I2C_SCL_PIN>, where I2C_SDA_PIN = 5 and I2C_SCL_PIN = 6. SharedI2cBus = Mutex<CriticalSectionRawMutex, I2cBus>. Its acquire() calls recover_i2c_bus(), then creates a controller at I2C_FREQUENCY_KHZ = 100. Recovery configures open-drain pins, pulses SCL nine times at five-microsecond half periods, and produces STOP by releasing SDA high while SCL is high.

Shared state and history

shared_state::init(psram) reserves SPS30_CAPACITY = 17,280 optional samples for one day, because HISTORY_WINDOW_MS = 86,400,000 and this task’s interval is 5,000 ms. It also reserves the SCD41 history. Sample<T> contains value and taken_at: Instant. HistoryStatus contains interval_ms, capacity, len, first_sequence, and next_sequence.

publish_sps30() briefly locks shared state and pushes Sample { value: measurement, taken_at: Instant::now() } when the history exists. publish_scd41() is the corresponding SCD41 operation. sps30_status() and scd41_status() copy their status. sps30_reading(sequence) and scd41_reading(sequence) copy one retained sample or return None.

MeasurementHistory<T> stores the permanent entry slice plus next, len, and pushed. new() rejects empty storage; push() writes, wraps the index, caps length, and increments pushed. capacity(), len(), first_sequence(), next_sequence(), get(), and private get_oldest() provide the exact ring-buffer interface. The sequence formula is first_sequence = pushed − len; it advances when a full buffer overwrites its oldest entry.

PSRAM

Psram::init() maps external PSRAM before tasks start. free_bytes() returns remaining mapped capacity. alloc_slice<T>(len, value) aligns the next address, checks arithmetic and bounds, fills all elements, advances the permanent allocation pointer, and returns a permanent mutable slice; it returns None when the request does not fit. If history allocation fails, both publish_* functions drop readings while sensor measurement and serial output continue.

Complete I²C startup scan interface

Although the SPS30 task does not call it after startup, the same I2cBus dependency also provides scan(). Firmware calls it before the bus enters SharedI2cBus. scan() calls public scan_i2c(), which probes every address from I2C_FIRST_ADDRESS = 0x03 through I2C_LAST_ADDRESS = 0x77.

I2C_ADDRESS_COUNT and MAX_I2C_DEVICES both represent the number of addresses in that inclusive range. Every probe uses an empty address-only write, so it does not select a device register. Each address gets I2C_SCAN_RETRIES = 3 attempts, separated by I2C_SCAN_RETRY_DELAY_MS = 10 ms; recovery and controller reconstruction happen before every attempt. print_scan_progress() displays a SCAN_PROGRESS_BAR_WIDTH = 30-character serial progress bar using # for completed segments and . for remaining segments.

I2cScanResult stores addresses: [u8; MAX_I2C_DEVICES] and count: usize. Its addresses() method returns the used prefix as &[u8]. Public print_scan_result() prints each returned address or prints that no I²C device acknowledged.

MeasurementHistory<T> stores next: usize, len: usize, and pushed: u64 in addition to its permanent entry slice. These exact types allow the ring buffer to use an array index for current position and length while retaining a non-repeating 64-bit sequence count for its entire uptime.
